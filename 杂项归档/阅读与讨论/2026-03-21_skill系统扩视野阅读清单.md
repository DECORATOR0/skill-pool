# 2026-03-21 skill系统扩视野阅读清单

## 这份清单为什么适合现在

你现在要解决的已经不只是“怎么 merge skill”，而是至少有下面这些设计变量：

- `skill` 到底是文本先验、API、程序，还是“目标 / 实现”二层结构
- 哪些 `skill` 可以晋升正式库，哪些只能留在候选池
- 失败产物应该保留“成品”，还是只保留“失败签名 / 元信息”
- 压缩应该在线做，还是等并行产物长起来以后再离线做
- 经验池的最小单元到底是什么
- `skill` 最终服务的是 planner、executor，还是分层消费

如果现在时间只够先读 3 篇，我建议优先：

1. `Memento-Skills`
2. `PolySkill`
3. `AFlow`

---

## 第一组：最贴你当前设想

### 1. Memento-Skills: Let Agents Design Agents

- 时间：2026-03-19 提交
- 链接：https://arxiv.org/abs/2603.18743
- 为什么贴：它几乎就是“外部 skill 库 + 路由 + 读写式反思学习 + 不改模型参数”的最新版变体，和你现在在想的东西高度同频。
- 读的时候重点看：`stateful prompts`、`read / write reflective learning`、`skill` 作为持久记忆的定义方式。

### 2. PolySkill: Learning Generalizable Skills Through Polymorphic Abstraction

- 时间：2025-10-17 提交，2026-03-02 更新
- 链接：https://arxiv.org/abs/2510.15863
- 为什么贴：它直接提出把 `skill` 的“做什么”和“怎么做”拆开，这对你后面做并行 candidate skill 再压缩特别重要。
- 读的时候重点看：`abstract goal` 和 `concrete implementation` 的分离能不能迁到你的 planner skill 设计里。

### 3. SkillWeaver: Web Agents can Self-Improve by Discovering and Honing Skills

- 时间：2025-04-09 提交
- 链接：https://arxiv.org/abs/2504.07079
- 为什么贴：它关注的是 agent 自己探索、练习、蒸馏出可复用 skill，并不断扩库。
- 读的时候重点看：`discover -> practice -> distill` 这条链，和你想做的“每个子任务先各自产 skill”之间能不能对齐。

### 4. Inducing Programmatic Skills for Agentic Tasks

- 时间：2025-04-09 提交，2025-08-29 更新
- 链接：https://arxiv.org/abs/2504.06821
- 为什么贴：它不是把 skill 主要当文本，而是当成可验证的程序，这能逼你重新想“planner skill”和“executable skill”的边界。
- 读的时候重点看：程序化 skill 的验证、迁移和复用机制，尤其是它为什么比纯文本 skill 更稳。

### 5. AFlow: Automating Agentic Workflow Generation

- 时间：2024-10-14 提交，2025-04-15 更新
- 链接：https://arxiv.org/abs/2410.10762
- 为什么贴：它把 workflow 设计本身视为搜索问题，而不是只在单条 prompt 上微调。
- 读的时候重点看：`workflow as code`、`tree-structured experience`、执行反馈如何进入搜索。

### 6. Automated Design of Agentic Systems

- 时间：2024-08-15 提交，2025-03-02 更新
- 链接：https://arxiv.org/abs/2408.08435
- 为什么贴：它把“让 agent 设计 agent”当成一类独立问题，这对你后面想从单技能设计，进一步抬到整套系统设计特别有用。
- 读的时候重点看：`Meta Agent Search` 和 archive 思想，尤其是“发现体制”本身能不能独立于当前 mode1 / mode2。

## 第二组：用来重构你对 skill 与 memory 的视角

### 7. Voyager: An Open-Ended Embodied Agent with Large Language Models

- 时间：2023-05-25 提交，2023-10-19 更新
- 链接：https://arxiv.org/abs/2305.16291
- 为什么读：经典 skill library 论文，重点不是 Minecraft，而是“自动课程 + 持续扩库 + 可组合 skill”这套结构。
- 读的时候重点看：为什么它强调可执行代码 skill，而不是只保留语言描述。

### 8. Reflexion: Language Agents with Verbal Reinforcement Learning

- 时间：2023-03-20 提交，2023-10-10 更新
- 链接：https://arxiv.org/abs/2303.11366
- 为什么读：它把失败后的反馈写进 episodic memory，再让 agent 下一轮使用。
- 读的时候重点看：你的经验缓冲到底应该保存原始轨迹、自然语言反思，还是更结构化的 failure signature。

### 9. MemGPT: Towards LLMs as Operating Systems

- 时间：2023-10-12 提交，2024-02-12 更新
- 链接：https://arxiv.org/abs/2310.08560
- 为什么读：它不是 skill 论文，但特别适合你重新思考“长期记忆 / 工作记忆 / 外部记忆”的分层。
- 读的时候重点看：哪些内容该放进 prompt，哪些应该外置成持久层，不要一股脑都塞在同一个上下文里。

### 10. Generative Agents: Interactive Simulacra of Human Behavior

- 时间：2023-04-07 提交，2023-08-06 更新
- 链接：https://arxiv.org/abs/2304.03442
- 为什么读：它把 memory、reflection、planning 这三块拆开了，适合拿来重审你现在“观察 -> 假设 -> 下一步验证”的记录机制。
- 读的时候重点看：观察、反思、计划这三层是否也能迁移成你的 skill 维护工作流。

### 11. Self-Discover: Large Language Models Self-Compose Reasoning Structures

- 时间：2024-02-06 提交
- 链接：https://arxiv.org/abs/2402.03620
- 为什么读：它提醒你“结构”不一定非要由人手写死，也可以先发现再固化。
- 读的时候重点看：你后面是不是可以让系统先发现 planner structure，再把它压缩进 skill，而不是先规定死字段。

## 第三组：回到 agent 基础动作层，再看科学工作流

### 12. ReAct: Synergizing Reasoning and Acting in Language Models

- 时间：2022-10-06 提交，2023-03-10 更新
- 链接：https://arxiv.org/abs/2210.03629
- 为什么读：很多后面的 agent 论文都默认继承了它的“思考 / 行动交织”范式。
- 读的时候重点看：你的 mode1 / mode2 到底是在改 reasoning 层、acting 层，还是两者的接口层。

### 13. Toolformer: Language Models Can Teach Themselves to Use Tools

- 时间：2023-02-09 提交
- 链接：https://arxiv.org/abs/2302.04761
- 为什么读：它帮助你把“工具调用能力”从“高层 skill”里剥出来单独看。
- 读的时候重点看：什么应该被学成工具使用习惯，什么才值得被封装成更高层 skill。

### 14. AutoLabs: Cognitive Multi-Agent Systems with Self-Correction for Autonomous Chemical Experimentation

- 时间：2025-09-30 提交
- 链接：https://arxiv.org/abs/2509.25651
- 为什么读：这是更偏高风险科学工作流的例子，适合你看多 agent、纠错、可靠性评估怎么一起设计。
- 读的时候重点看：它怎么把 modular design、reasoning capacity、self-correction 放到同一个评估框架里。

### 15. Enhancing Agentic Autonomous Scientific Discovery with Vision-Language Model Capabilities

- 时间：2025-11-18 提交
- 链接：https://arxiv.org/abs/2511.14631
- 为什么读：它把图表和中间结果当作可检验 checkpoint，这对科学型 agent 很有启发。
- 读的时候重点看：你能不能也把某些中间产物提升成显式可校验节点，而不是只盯最终答案对错。

---

## 建议阅读顺序

1. 先读 `Memento-Skills`、`PolySkill`、`AFlow`
2. 再读 `SkillWeaver`、`Inducing Programmatic Skills`
3. 然后回头补 `Reflexion`、`MemGPT`、`Generative Agents`
4. 最后用 `AutoLabs` 和 `科学发现` 这两篇把视角拉回你的科学工作流场景

---

## 读的时候最值得记下来的 6 个问题

1. 你的 `skill` 最小单位到底是什么：文本、程序、API、planner prior，还是它们的组合？
2. 一个 `skill` 晋升到正式库之前，需要满足什么阈值：单题成功、family 成功、稳定复现，还是可验证通过？
3. 失败产物应该保留哪一层：全文、摘要、错误标签、工具序列、参数模式，还是只留 critic 结论？
4. 压缩到底该发生在什么时候：每轮在线压，还是并行长出十几二十条之后再离线压？
5. `skill` 的消费方到底是谁：router、planner、executor、parameter worker，还是按层拆开？
6. 你的经验池有没有必要从“自然语言经验”升级成“结构化失败模式库”？

## 一句提醒

基于这些论文，我对你当前设想的一个强烈判断是：后面最该认真设计的，未必是“怎么更聪明地 merge”，而是“成功 skill、失败 skill、失败模式、workflow 经验”这四类东西到底怎么分层保存、何时晋升、谁来消费。
