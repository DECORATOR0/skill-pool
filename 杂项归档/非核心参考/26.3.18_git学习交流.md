# Git 协作速记

日期：2026-03-18

## 1. 认证

- 省事：`HTTPS + Git Credential Manager`
- 长期稳定：`SSH Key`
- 双人协作时，每个人用自己的账号和自己的认证
- 不共享 `SSH 私钥`、`PAT`、账号密码

仓库专用凭据只适合机器或自动化：

- `Deploy Key`
- `Repo / Project Access Token`

不适合两个人共用一把 key 来开发。

## 2. 本地仓库推到自己的远端

先在 GitHub / GitLab / Gitee 创建一个空仓库，最好不要勾选：

- `README`
- `.gitignore`
- `LICENSE`

### 本地目录还不是 Git 仓库

```powershell
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin <repo-url>
git push -u origin main
```

### 本地已经是 Git 仓库

```powershell
git status
git branch
git remote -v
```

没有远端就加：

```powershell
git remote add origin <repo-url>
```

远端地址错了就改：

```powershell
git remote set-url origin <repo-url>
```

把主分支统一成 `main`：

```powershell
git branch -M main
git push -u origin main
```

补充：

- `git remote add origin ...` 只是建立链接，不会上传任何代码
- `git push -u origin main` 只推 `main`
- `git push --all origin` 才是推所有本地分支

## 3. 双人协作的最小规则

- `main` 放稳定基线
- 每个人一个自己的开发分支
- 你这边用 `xsy`
- 对方用自己的分支名
- 不直接在 `main` 上长期开发

### 推荐流程

从最新 `main` 拉出自己的分支：

```powershell
git checkout main
git pull origin main
git checkout -b xsy
```

开发并提交：

```powershell
git add .
git commit -m "Describe the change"
git push -u origin xsy
```

同步主线：

```powershell
git fetch origin
git checkout xsy
git merge origin/main
```

或者：

```powershell
git rebase origin/main
```

查看自己相对 `main` 改了什么：

```powershell
git log --oneline origin/main..origin/xsy
git diff origin/main...origin/xsy
```

## 4. 当前这个仓库的分支约定

- 默认分支应为 `main`
- `xsy` 只是你的开发分支
- `main` 作为基线
- 开发完成后，从 `xsy` 合并回 `main`

GitHub 网页里改默认分支的位置：

- `Settings -> General -> Default branch -> main`

本地同步远端默认分支信息：

```powershell
git fetch origin
git remote set-head origin -a
git remote show origin
```

如果输出里看到 `HEAD branch: main`，说明默认分支已经是 `main`。

## 5. 被忽略目录怎么协作

当前仓库里主要被忽略的是：

- `project_skills/runs/`
- `benchmark/`

这类目录一般不直接进 Git，因为：

- 体积大
- 噪音多
- 很多内容可重复生成

协作时不要靠整个 `runs/` 目录同步，而是把下面这些放进 Git：

- 代码
- `skill` 定义
- 配置
- prompt
- 实验结论
- 关键参数
- 错误摘要

推荐做法：

- `runs/` 继续忽略
- 在 `docs/experiments/` 之类的目录提交实验记录
- 真要共享完整运行产物，再单独发压缩包或放外部存储

## 6. 常见误区

- 不要把 token 直接写进远端 URL
- 不要把私钥发给别人
- 不要两个人共用一个账号开发
- 不要长期只在各自分支上堆很多天再一次性合并
- 不要把所有运行产物都直接塞进 Git
