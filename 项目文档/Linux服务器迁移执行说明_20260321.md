# Linux服务器迁移执行说明

本文档给服务器上的执行型 AI 使用。目标是：

1. 从远端 `git` 拉取当前开发分支代码。
2. 单独下载 `benchmark` 数据，不通过 `git` 传输大文件。
3. 在 Linux 服务器上建立可运行的 `conda` 环境。
4. 按当前项目结构补齐软链接和 Linux 本地配置。

## 一、仓库拉取

假设服务器工作目录为 `~/work/skill-pool`：

```bash
mkdir -p ~/work
cd ~/work

if [ ! -d skill-pool/.git ]; then
  git clone -b dev/linux-sync-20260321 git@github.com:DECORATOR0/skill-pool.git
else
  cd skill-pool
  git fetch origin
  git checkout dev/linux-sync-20260321
  git pull --ff-only origin dev/linux-sync-20260321
fi
```

如果上面执行了 `git clone`，后续命令默认都在：

```bash
cd ~/work/skill-pool
```

## 二、Conda环境

如果服务器没有 `conda`，先安装 `Miniconda` 或 `Mambaforge`。已有 `conda` 时直接继续。

优先使用仓库根目录的环境文件：

- `environment.skill-eval.yml`

推荐环境名：`earth-bench-skill-eval`

```bash
cd ~/work/skill-pool

conda env create -f environment.skill-eval.yml
conda activate earth-bench-skill-eval
```

如果环境已经存在，改用：

```bash
cd ~/work/skill-pool

conda env update -f environment.skill-eval.yml --prune
conda activate earth-bench-skill-eval
```

当前环境文件覆盖的核心 Python 依赖包括：

- `numpy`
- `pandas`
- `scipy`
- `pyyaml`
- `httpx`
- `rasterio`
- `gdal`
- `opencv`
- `scikit-image`
- `statsmodels`
- `ruptures`
- `matplotlib`
- `transformers`
- `huggingface_hub`
- `openai`
- `fastmcp`

如果 `opencv` 在服务器上报缺少系统库，再补：

```bash
sudo apt-get update
sudo apt-get install -y libgl1 libglib2.0-0
```

## 三、Benchmark数据迁移

当前仓库不通过 `git` 同步以下目录：

- `benchmark/`
- `project_skills/benchmark/`
- `project_skills/runs/`

其中 `project_skills/benchmark` 在 Windows 上是一个指向外层 `benchmark/benchmark` 的目录连接。Linux 上请按下面方式重建。

### 1. 下载 Earth-Bench 数据

先安装好上面的 conda 环境，然后执行：

```bash
cd ~/work/skill-pool
conda activate earth-bench-skill-eval

mkdir -p benchmark/benchmark/data

python - <<'PY'
from huggingface_hub import snapshot_download

snapshot_download(
    repo_id="Sssunset/Earth-Bench",
    repo_type="dataset",
    local_dir="benchmark/benchmark/data",
    local_dir_use_symlinks=False,
    resume_download=True,
)
PY
```

说明：

- 该数据集约 `16.6GB`，本地 Windows 副本约 `17.5GB`。
- 本地现有数据目录结构与 Hugging Face 下载缓存格式一致，推断可直接这样拉取。
- 下载会把 `question1/` 到 `question248/` 这类目录放到 `benchmark/benchmark/data/` 下。

### 2. 建立项目内软链接

```bash
cd ~/work/skill-pool

rm -rf project_skills/benchmark
ln -s ../benchmark/benchmark project_skills/benchmark
```

验证：

```bash
ls -ld project_skills/benchmark
ls project_skills/benchmark | head
ls project_skills/benchmark/data | head
```

## 四、Linux本地配置

当前仓库中的 `.local.json` 配置是 Windows 路径，不能直接在 Linux 上使用。需要复制出 Linux 版。

建议至少复制这两个：

- `project_skills/configs/system.dualmode_mode1.local.json`
- `project_skills/configs/system.dualmode_mode2.local.json`

生成 Linux 版：

```bash
cd ~/work/skill-pool

cp project_skills/configs/system.dualmode_mode1.local.json project_skills/configs/system.dualmode_mode1.linux.json
cp project_skills/configs/system.dualmode_mode2.local.json project_skills/configs/system.dualmode_mode2.linux.json
```

然后把这几类字段统一改掉：

1. `paths.workspace_root`
2. `paths.prompt_root`
3. `paths.run_root`
4. `paths.skill_library_root`
5. `paths.experience_buffer_path`
6. `paths.dataset_path`
7. `paths.converted_dataset_path`
8. `paths.docs_root`
9. `runtime.python_executable`
10. `runtime.shell_program`

Linux 推荐值示例：

```json
{
  "paths": {
    "workspace_root": "/root/work/skill-pool/project_skills",
    "prompt_root": "/root/work/skill-pool/project_skills/prompts_mode1",
    "run_root": "/root/work/skill-pool/project_skills/runs/dualmode_mode1",
    "skill_library_root": "/root/work/skill-pool/project_skills/runs/dualmode_mode1/skill_library",
    "experience_buffer_path": "/root/work/skill-pool/project_skills/runs/dualmode_mode1/runtime_state/experience_buffer.jsonl",
    "dataset_path": "/root/work/skill-pool/project_skills/benchmark/question.json",
    "converted_dataset_path": "/root/work/skill-pool/project_skills/data/converted/earth_bench_skill_rl/question.json",
    "docs_root": "/root/work/skill-pool/project_skills/docs"
  },
  "runtime": {
    "python_executable": "/root/miniconda3/envs/earth-bench-skill-eval/bin/python",
    "shell_program": "bash"
  }
}
```

注意：

- `prompt_root` 对 mode1 和 mode2 不同，分别是 `prompts_mode1` 和 `prompts_mode2`。
- `converted_dataset_path` 已在仓库中，不依赖大数据下载。
- 当前代码里的 `run_shell` 默认更偏向 PowerShell 习惯；如果后续实际运行用到了它，建议再把代码改成兼容 `bash -lc`。如果暂时不改，也可先在服务器上安装 `pwsh` 并把 `shell_program` 设为 `pwsh`。

## 五、可选补充文件

如果运行过程中发现以下文件缺失，再额外补齐：

- `benchmark/benchmark/question.json`
- `benchmark/benchmark/model_results.csv`

说明：

- 当前训练主流程实际读取的是 `project_skills/data/converted/earth_bench_skill_rl/question.json`。
- 但部分旧流程、调试流程或 RGB 感知相关逻辑可能仍会引用原始 `question.json` 或 `model_results.csv`。
- 如果服务器上缺这两个文件，而当前任务又没有用到对应流程，可以先不补；一旦报缺失，再单独同步这两个小文件。

## 六、基础验证

先做导入与工具层烟雾测试：

```bash
cd ~/work/skill-pool
conda activate earth-bench-skill-eval

python -m project_skills.agent.skill_eval.test_all_tools_smoke \
  --output-dir project_skills/benchmark/out/linux_smoke
```

再做一次最小训练验证：

```bash
cd ~/work/skill-pool
conda activate earth-bench-skill-eval

python -m project_skills.nlrl_skills.cli \
  --config project_skills/configs/system.dualmode_mode1.linux.json \
  train-tasks \
  --start-index 0 \
  --count 1 \
  --run-name linux_smoke \
  --reset-skill-library \
  --reset-experience-buffer
```

如果只验证 mode2，把配置文件换成：

```bash
project_skills/configs/system.dualmode_mode2.linux.json
```

## 七、建议的服务器执行顺序

```bash
git pull
conda activate earth-bench-skill-eval
python - <<'PY'
from huggingface_hub import snapshot_download
snapshot_download(
    repo_id="Sssunset/Earth-Bench",
    repo_type="dataset",
    local_dir="benchmark/benchmark/data",
    local_dir_use_symlinks=False,
    resume_download=True,
)
PY
rm -rf project_skills/benchmark
ln -s ../benchmark/benchmark project_skills/benchmark
```

然后再编辑 Linux 配置并开始跑实验。
