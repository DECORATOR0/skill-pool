# 2026-03-20 双模式Skill实验代码构建任务提示词

## 使用说明

- 这份提示词用于发给另一个 AI，让它只负责把代码和运行脚本构建出来
- 不要求它实际启动训练或评估
- 重点是把 `mode1` 和 `mode2` 的代码路径、prompt 路径、配置路径、运行脚本拆干净，避免后续手工运行时混乱

## 可直接发送的提示词

```text
你现在在仓库 `D:\skills-evo\project_skills` 中工作。

任务目标不是直接跑实验，而是先把“双模式 skill 实验”所需的代码和运行脚本完整构建出来，并明确告诉我之后应该在哪个目录下执行哪些命令。

请注意：
1. 不要自动启动任何长时间训练或评估任务。
2. 我这次只要代码、配置、prompt、脚本和运行说明，不要替我真的开跑。
3. mode2 不是“只改几段 prompt”这么简单；如果当前架构不足以支持 planner-oriented skill，就请你补出最小必要的并行/兼容实现，而不是伪装成 prompt-only 改造。

你需要完成的事情如下。

一、先检查现有架构，再决定最小改造方案

请先检查当前仓库里与 skill 训练/评估相关的核心代码，至少包括：
- `D:\skills-evo\project_skills\project_skills\nlrl_skills`
- `D:\skills-evo\project_skills\project_skills\agent\skill_eval`
- `D:\skills-evo\project_skills\project_skills\prompts`
- `D:\skills-evo\project_skills\project_skills\configs`

- `mode1` 保持现有 executor-oriented skill 范式
- `mode2` 实现 planner-oriented skill 范式

如果当前 `nlrl_skills` 运行时只能把 skill 注入 executor，那么请你为 `mode2` 增加一条平行或兼容的运行路径，使 skill 真正服务于 planner 及其下游协作流程，而不是继续把 planner 风格的 skill 文本硬塞给 executor。

二、请实现两种模式

### mode1：executor-oriented skill

保持当前主范式：
- router 匹配 skill
- skill 主要面向 executor
- skill 负责提供工具链约束、默认流程、allowed-tools、脚本调用规则、停止条件等

### mode2：planner-oriented skill

目标是实现一套与协作者“六个优良 skill”更接近的范式：
- router 先匹配 skill
- skill 主要面向 planner，而不是直接面向 executor
- skill 负责提供工具范围、family rules、stepwise execution pattern、parameter policy、stop guidance 等高层先验
- 如果需要，请让 planner、parameter worker、executor 形成一条清晰的协作链

这里不要偷换概念：
- 如果只是把 prompt 改成更抽象，但运行时依然是“skill 全文注入 executor”，那不算真正的 mode2
- 真正的 mode2 至少要在 skill 消费层面与 mode1 区分开

三、训练与评估要求

请为两种模式都接上“训练阶段 + 评估阶段”的完整代码路径，但这次不要实际执行。

实验要求：
- 数据范围：按当前项目中 Earth Bench 的全量训练/评估流程接入；请以仓库现有数据组织为准，不要瞎编路径
- `skill_count_limit = 6`
- `max_iterations_per_task = 4`
- 最大工具链/step 长度上限设为 `20`

如果当前代码中这些值不是 20/4/6，请为本次双模式实验补出独立配置，不要直接污染原有默认配置。

四、请输出两个可直接运行的脚本

请新增两个脚本，分别负责“训练后接评估”，但不要自动启动：

1. mode1 脚本
- 负责 executor-oriented 模式
- 先训练，再评估
- 输出目录、日志目录、skill library 目录要与 mode2 隔离

2. mode2 脚本
- 负责 planner-oriented 模式
- 先训练，再评估
- 输出目录、日志目录、skill library 目录要与 mode1 隔离

脚本形式你自行判断，可用 `.ps1`、`.bat` 或 Python 包装脚本，但要求：
- 我后续能在命令行中直接运行
- 路径清晰
- 参数清晰
- 不需要我再手工拼很长的命令

五、代码组织要求

请优先采用“平行模式”而不是“把所有逻辑揉进一套 prompt 里”：
- mode1 有自己的一套 prompt / config / runner
- mode2 有自己的一套 prompt / config / runner
- 尽量复用公共代码，但不要让两套实验互相污染

如果你需要新增文件，请优先放在合理位置，例如：
- `D:\skills-evo\project_skills\project_skills\configs\`
- `D:\skills-evo\project_skills\project_skills\prompts\`
- `D:\skills-evo\project_skills\project_skills\scripts\`
- 必要时补充新的 runtime / planner / worker 相关代码

六、交付要求

完成代码后，请不要运行长实验，只需要给我以下结果：

1. 两个运行脚本的绝对路径
2. 我应该在哪个目录下打开命令行
3. mode1 的准确运行命令
4. mode2 的准确运行命令

七、重要约束

- 不要替我启动训练
- 不要替我启动评估
- 不要替我做结果收集和结果分析
- 只把代码和脚本准备好
- 如果你发现某个地方要真正实现 mode2 必须做架构改造，就直接做最小必要改造，不要假装已经支持

最后，完成后请用中文回复我。
```
