## 最终落地结果

### 1. 两种模式的实验状态是隔离的

本轮最终确认：

- `run_root` 独立
- `skill_library_root` 独立
- `experience_buffer_path` 独立

具体分别是：

- `mode1`
  - `runs/dualmode_mode1`
  - `runs/dualmode_mode1/skill_library`
  - `runs/dualmode_mode1/runtime_state/experience_buffer.jsonl`
- `mode2`
  - `runs/dualmode_mode2`
  - `runs/dualmode_mode2/skill_library`
  - `runs/dualmode_mode2/runtime_state/experience_buffer.jsonl`

因此：

- `mode1` 清库、积累经验，不会污染 `mode2`
- `mode2` 清库、积累经验，也不会反向污染 `mode1`

### 2. 仍然共享的部分

不是完全物理隔离的部分有：

- 工作区代码
- 数据集路径
- 模型/API 配置主体
- 共享 prompt 目录

说明：

- `prompt_root` 已经分为 `prompts_mode1` 和 `prompts_mode2`
- 但当前实现保留了 fallback
- 如果 mode 专属目录里没有某个 prompt，会回退到共享 `project_skills/prompts`

因此当前结论是：

- 实验状态隔离了
- 代码与部分公共 prompt 仍然共享

### 3. 用户实际启动时的确认

用户后来在 PowerShell 中执行了：

```powershell
powershell -ExecutionPolicy Bypass -File "D:\skills-evo\project_skills\project_skills\scripts\run_dualmode_mode1_train_eval.ps1"
```

并进一步确认了：

- 这条命令是正确的启动方式
- 它会在当前 PowerShell 中正式开始 `mode1` 的训练后评估流程
- 不是检查命令，而是真正开跑
